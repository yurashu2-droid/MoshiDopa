# セッションと履歴画面の責務分離

対象の基点: `96d79a80e0c6de7430f066fb0b88bb2ca39535dc`。

## 設計判断

既存の Kotlin / Android View アプリに合わせ、軽量なレイヤー分離とコンポジションを採用する。
計測ルールは Android から独立させ、永続化はインターフェース越しに呼ぶ。
画面には描画に必要な値と操作コールバックを渡し、画面遷移・保存状態の所有者を明確にする。
既存の小規模アプリに対し、DI フレームワーク、Compose 移行、多数の Gradle モジュールを
今回導入する必要性はない。既存の domain の計算関数をそのまま活用する。

## 変更後の責務

| 要素 | 責務 |
| --- | --- |
| `TrackingService` | OSイベント、Foreground Service、通知、表示タイミング、オーバーレイ |
| `TrackingSession` | セッション開始、単調増加時計による経過時間、途中保存、終了、日付分割の選択 |
| `RecordRepository` | セッションが必要とする保存操作の契約 |
| `Store` | SQLiteと既存設定へのアクセス、終了時の分割記録の一括保存 |
| `MainActivity` | ライフサイクル、画面遷移、保存・復元する画面状態、各画面の組み立て |
| `HistoryScreen` | 渡された履歴スナップショットの描画、日付・展開・明細操作の通知 |
| `HistoryScrollView` | ドラッグ・速度計測・スクロール終了アニメーション |
| `PageUi` | 共通の文字・ボタン・入力欄・金額表示の見た目 |

`TrackingService → TrackingSession → RecordRepository ← Store` の依存関係にする。
セッションは Android クラスに依存しない。日時は呼び出し側から渡し、日付分割の
タイムゾーンもテスト時に指定できる。手動計測の途中保存は開始時刻をリセットしない。

履歴画面は Activity の可変フィールドや Store を直接操作しない。
操作結果をコールバックで返し、Activity が状態を更新して再描画する。
遷移によって取り外されたグラフの遅延コールバックが画面状態を更新しないよう確認を追加した。

## 保存の振る舞い

終了した記録の先頭区間の更新と、翌日以降の区間の挿入を同じトランザクションにまとめた。
途中の挿入失敗は先頭の更新もロールバックする。更新対象の行が存在しない場合も失敗として扱い、
後続区間だけが保存されることを防ぐ。保存成功後にだけセッションを終了状態にする。
再試行はセッションAPI上で可能だが、サービスに永続的な再試行キューを追加したわけではない。

DB名、バージョン2のスキーマ、設定キー、applicationId、単価の計算式は維持する。
自動計測は日付で分割し、手動計測は1活動として保存する従来の方針も維持する。

## 検証

今回追加したテスト:

- `TrackingSessionTest` 7件: 壁時計変更と単調増加時計、日付分割、手動の単一区間、
  二重終了、二重開始防止、保存失敗後の再試行、負の経過時間。
- `StoreTransactionTest` 2件: 後続区間の挿入失敗時のロールバックと再試行、
  更新対象が存在しない場合の孤立した区間の挿入防止。
  UUID付きの専用DBを作って破棄し、通常のDBと設定は変更しない。

今回の環境では Gradle 9.2.1 の取得が `Network is unreachable` で失敗し、
ビルド・JUnit・Android計装テスト・Lintは実行できていない。
追加テストを成功済みと扱わないこと。パッチの適用確認と差分の静的レビューのみ実施。

Android Studio / JDK 21 / 必要なAndroid SDKを用意した環境で実行する:

```sh
bash gradlew :app:assembleDebug :app:testDebugUnitTest :app:lintDebug
bash gradlew :app:connectedDebugAndroidTest
```

Windowsでは `bash gradlew` を `.\gradlew.bat` に置き換える。
既存のUIテストは設定・AppOpsを書き換えるため、README指定の専用エミュレーターを使用する。
履歴の日付選択、遅いドラッグ・速いスワイプ、展開、明細遷移、回転後の復元を確認する。

## 残る設計上の課題

この変更で全画面の責務分離が完了するわけではない。初期設定・ホーム・明細画面の描画は
まだActivityに残り、画面遷移も文字列ベース。Storeは設定アクセスとDBアクセスを兼ねる。
また、MainActivityとServiceは従来の静的なLiveStateを介して連携している。
今後は今回の画面境界を踏襲して画面を分離し、型付きの画面状態と観測可能な計測状態へ
段階的に移行できる。OSイベントの配信遅延や長時間Dozeへの対応は今回の変更対象外。
