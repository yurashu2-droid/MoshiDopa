# 明細と節目演出

## 今回の動作

- 自動計測中の値札を、黒地から紙色・黒い数字に変更。
- 対象アプリを離れると計測は即停止し、明細プレビューを直ちに表示。
- 同じアプリへ戻った場合も、終了済みの記録を再開せず新しい計測区間として扱う。
- プレビューは8秒表示し、タップで該当記録の明細へ。「閉じる」でも消せる。
- 画面ロック中とTIME COST自体の表示中は重ねない。他の対象アプリが計測中ならライブ金額を優先し、履歴に記録を残す。
- 値札のメイン金額は「今回」、その下に「今日のトータル」を薄灰色で表示。明細は「今回」。SPENDの黒い金額に赤い取消線、INVESTは取消線なしの自己投資明細。
- 共有PNGにも同じ明細デザインと注意書きを反映。既存の設定ダッシュボード・対象アプリ一括選択・保存データは維持。

## 品物

ライブ値札では、今回のセッション換算額が10〜90円なら10円ごと、100〜900円なら100円ごと、1000円以降なら200円ごとに、落下演出を最大1個だけ生成する。品物は駄菓子（10円）、チョコレート（100円）、コーヒー（200円）から、到達した金額に対応するものを選ぶ。落下中に次の金額へ到達した場合は、落下完了後に保留分を順番に再生する。

これは経過時間を視覚化する演出であり、購入可能数・購入履歴・終了明細の比較データとは結び付けない。アプリ離脱・画面OFF・サービス停止で物体と描画ループを破棄し、新しいセッションでは周期をリセットする。遅延後に過去の分をまとめて表示せず、同時表示数と寿命にも上限を設ける。

終了明細で使う`Milestones`と、ライブ落下演出の`MoneyDropScheduler`は別定義。値札内の高さ38dp欄ではなく、値札の背後にある透明な描画ウィンドウで描画する。

## 動きの設計

motion-directorの指針に基づき、値札のサイズと金額を固定し、独立した透明レイヤーで物体の運動だけを見せる。
画面上端から重力で加速落下 → 値札の上辺に衝突 → 反発・回転 → 摩擦で横へ転がる → 端から画面外へ落下、という物理的な流れにする。駄菓子は軽く跳ね、コーヒーは重めに着地して短くゴトゴト揺れる。
音・振動・紙吹雪・コンボ・次の品物までの進捗表示は使わない。
ドラッグは従来どおり指に追従し、演出中も操作可能。画面離脱で演出キャンセル。
設定から品物表示とアニメーションを個別にOFF可能。Androidのアニメーション無効時は静止した品物と言葉のみ。

## 検証手順

Android Studioで`app`をRun。自動計測を開始して対象アプリを開き、10円・20円…、100円・200円…の到達時に落下→衝突→回転→退出が起きること、100円でチョコレート、200円でコーヒーへ切り替わることを確認する。対象アプリを離れると明細プレビューが出て、落下演出は重ならないことも確認する。
検証専用AVDでは`gradlew.bat :app:connectedDebugAndroidTest`で操作テスト可能（テストは設定を変更するため個人用端末では実行しない）。
`FeedbackTest`で即時表示・表示期限・しきい値を検証。
`MvpFlowTest`でプレビュー表示→タップで明細、手動→共有、落下・着地・保持・静止のスクリーンショットを検証する。落下ウィンドウは`FLAG_NOT_TOUCHABLE`で背後のアプリに入力を渡すため、実機/エミュレーターでスクロールと値札のドラッグも確認する。
画像は`docs/screenshots/feedback/files/`。旧スクリーンショットや過去のREADME仕様より、この追補が優先。

## 検証結果

デバッグAPK生成、単体テスト、Lint、Android 15相当の専用`Medium_Phone_AR35`での自動計測テストを確認済み。約10円到達時の駄菓子、100円到達時のチョコレート、対象アプリ離脱・画面OFF時の後片付け、YouTube背後のタップ透過を検証した。通常速度の画面録画は`docs/screenshots/physics/time-cost-auto-candy-final.mp4`と`docs/screenshots/physics/time-cost-auto-coffee-final.mp4`に保存している。

録画ファイルの保存と画面フレームの確認は済み。端末上での録画再生による触感評価は未実施。

OSによってアプリ切替イベントの遅れや重ねて表示の制限がある。直ちに表示するのはイベント検出後であり、厳密な画面切替時刻保証ではない。
対象アプリ間の連続切替では最新の区間を優先。複数区間のプレビューを順番に押し出すことはしない。
絵文字の見た目は端末のフォントに依存。長時間・日付またぎ・文字サイズ拡大時の追加実機検証は必要。
